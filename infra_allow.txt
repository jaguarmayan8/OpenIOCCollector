# infra_allow.txt - shared-infrastructure filter for the domain CDB list.
#
# WHY THIS FILE EXISTS
#   URLhaus reports the URL that hosts or delivers a payload, not the domain
#   that is malicious. On 2026-11-19, 98,747 of 116,572 rows (85%) pointed at
#   shared platforms - github.com, raw.githubusercontent.com, cdn.discordapp.com.
#   Extracting the host from those rows puts github.com: in the CDB list, so
#   rules 100101/100102 fire on every legitimate GitHub fetch in the lab and
#   block the tooling that maintains this repo.
#
#   Suppressing them loses nothing: the payload path is the IOC
#   (github.com/user/repo/raw/x/payload.exe), and the whole URL is preserved
#   in the day's release asset.
#
# TWO TIERS - they are NOT interchangeable
#
#   platform <domain>
#     The registrable domain is shared infrastructure. Suppressing it also
#     suppresses every subdomain, because no subdomain is one tenant:
#     raw.githubusercontent.com, cdn.discordapp.com, gist.github.com.
#     Correct for code hosting, CDNs, pastebins, shorteners, tunnels.
#
#   hosting <domain>
#     Multi-tenant hosting. The bare domain is noise, but each subdomain is a
#     single customer - evil.000webhostapp.com is a real, precise IOC and must
#     stay blockable. Only the apex is suppressed.
#     Wrong choice here destroys real detections: blocking based on
#     github.io would also block jaguarmayan8.github.io (this project's own
#     dashboard), while evil.github.io is worth blocking.
#
# Matching is on label boundaries: an entry `github.com` matches github.com and
# a.github.com but NOT notgithub.com or github.com.evil.tld.
#
# Extend freely - one entry per line, `#` starts a comment.
